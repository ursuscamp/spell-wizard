# Simplify Guessing UI - Technical Design

## Architecture Overview

This feature is a focused frontend change to the spelling session page. It simplifies the in-session guessing experience by removing the secondary sparkle session log panel and reshaping the existing layout so the primary spelling interaction becomes the sole visual focus.

The change fits into the current session architecture without modifying backend session logic, scoring, reward generation, or adaptive word selection. The session page will continue to consume the existing session view and attempt response data, but it will no longer render the sidebar content that currently explains scoring, adaptive practice, and turn-based reward events.

Key architectural decisions:

- Keep the change isolated to the session UI layer.
- Preserve all existing session APIs, state transitions, and server-side data recording.
- Reuse the existing primary guessing card and related composables instead of introducing a replacement sidebar pattern.
- Allow any still-needed active-turn feedback to appear within the main session area rather than in a separate column.

## Interface Design

| Interface | Input | Output | Description |
|-----------|-------|--------|-------------|
| `SessionPage` | `route profile id`, existing session state | rendered session UI | Displays the spelling session guessing experience for a child profile |
| `submitAttempt` | `{ guess: string }` | `AttemptResponse` | Submits a spelling attempt and updates the active prompt state |
| `startSession` | existing session initialization input | `SessionView` | Starts or resumes a spelling session |
| `replayPromptAudio` | current prompt context | spoken prompt playback | Replays the spoken word prompt during the session |

No new public interfaces are required for this feature. Existing interfaces remain unchanged.

## Data Models

This feature does not require new data models or schema changes.

Relevant existing UI-facing data remains:

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `currentPrompt` | session prompt object | existing shape | The active word prompt shown in the guessing UI |
| `attemptsUsed` | number | `0-3` in current flow | Number of attempts used for the current prompt |
| `pointsEarned` | number | existing scoring rules | Points awarded for a successful prompt resolution |
| `rewards` | reward event array | optional, transient UI state | Reward feedback generated by the current turn |
| `sessionProgress` | session progress object | existing shape | Progress indicators such as words completed and session points |

#### Schema Changes

- None.

## Key Components

### Session Page

**Responsibilities:**
- Render the guessing UI for the active spelling session
- Display the primary prompt, answer input, session progress, and turn feedback
- Coordinate layout changes after sidebar removal

**Public API:**
- `startSession(): Promise<SessionView>`
- `submitAttempt(input: { guess: string }): Promise<AttemptResponse>`
- `replayPromptAudio(): void`

**Dependencies:**
- Session state composables and page-level reactive state
- Prompt voice composable
- Fun effects composable
- Shared session types

### Reward Feedback Presentation

**Responsibilities:**
- Show any active-turn reward feedback that remains necessary after sidebar removal
- Keep reward visibility inside the primary session area if retained

**Public API:**
- `render(rewards: RewardEvent[]): UI`

**Dependencies:**
- Existing reward event payloads from session responses

### Session Layout Styles

**Responsibilities:**
- Remove the two-column dependency created for the sidebar layout
- Ensure the main session card expands cleanly on desktop and mobile

**Public API:**
- CSS classes and layout rules used by the session page

**Dependencies:**
- Existing page-level CSS and responsive breakpoints

## User Interaction

#### Invocation Patterns

- UI interaction on the spelling session page
- Spoken prompt replay during the active spelling session
- Guess submission through the existing answer form

#### Flows

1. User opens a child profile's spelling session page.
2. The page loads the current spelling session and active prompt.
3. The user hears or replays the spoken prompt.
4. The user enters a guess and submits it.
5. The page shows correctness, retry, or correction feedback in the main session experience.
6. The layout remains focused on the active prompt and progress without a side sparkle session log.

Error and recovery paths:

- If session loading fails, the existing page-level error behavior remains unchanged.
- If attempt submission fails, the existing error handling remains unchanged.
- If reward feedback is retained, it must not depend on a removed sidebar container to remain visible.

#### Input/Output Examples

```markdown
User opens /profile/:id/session
-> Session page loads current spelling session
-> Main prompt card is shown without sidebar

User taps replay
-> Spoken prompt audio plays

User submits a guess
-> Correct/retry/correction feedback appears in the main session area
-> Session progress updates as before
```

## Error Handling

| Error Code | Condition | Error Data | Recovery |
|------------|-----------|------------|----------|
| `SESSION_LOAD_FAILED` | Session data cannot be loaded | existing page error payload | Show existing error state or retry path |
| `ATTEMPT_SUBMIT_FAILED` | Guess submission fails | existing attempt error payload | Preserve input if applicable and allow retry |
| `REWARD_FEEDBACK_HIDDEN` | Reward feedback becomes inaccessible after layout change | active reward event context | Move reward feedback into the primary session area |

No new backend error types are introduced.

## Platform Considerations

| Platform | Consideration | Approach |
|----------|---------------|----------|
| Desktop browsers | Existing two-column layout will leave unused space if not updated | Convert to a single focused main-content layout |
| Mobile browsers | Sidebar removal must not leave duplicate spacing or stacked empty sections | Remove sidebar containers and preserve compact vertical flow |

## Trade-offs

**Decision**: Remove the sparkle session log sidebar without introducing a replacement panel in this scope.

**Reasoning:**
- Matches the user's request for a simpler guessing UI
- Reduces visual clutter and competing information during active spelling
- Keeps the change small and low risk by avoiding backend or product-flow redesign

**Impact:**
- Users lose the sidebar's inline explanations for scoring and adaptive practice
- Any desired reward feedback must be retained somewhere in the main session area or intentionally dropped
- The session page becomes more focused but offers less passive explanatory context during play

## Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Reward feedback becomes less visible after sidebar removal | Medium | Medium | Keep important active-turn reward messaging within the primary session area |
| Desktop layout looks sparse or stretched after removing a column | Medium | Medium | Update the session container and width rules for a deliberate single-column composition |
| Users lose useful scoring context from the removed panel | Medium | Low | Retain only essential turn feedback inline and avoid reintroducing static sidebar copy |
| UI-only change accidentally affects session behavior | Low | High | Limit changes to layout and presentation layers; verify session flow behavior remains unchanged |
